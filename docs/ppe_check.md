# Проверка средств защиты: каска и жилет

Отдельное измерение рядом с календарным планом. Каска не зависит от того, какой сегодня
этап, поэтому проверке не нужен ни план, ни правила по технике — только кадр с человеком.

## Как устроено

```
кадр (фото или кадр ролика)
   └─► детектор людей (torchvision COCO, порог 0.5)
          ├─ рост ниже 80 px       → не судим
          ├─ ширина меньше ¼ роста → это не человек
          └─► вырезка
                ├─ голова с плечами ──► ResNet-18: каска или нет
                └─ фигура целиком   ──► ResNet-18: жилет или нет
```

**Вход один для фото и видео.** Кадры ролика разбираются тем же путём, что фотографии;
разница только в показе — ролик отдаётся проигрывателем с нарисованной разметкой.

## Почему обученные сети, а не сравнение фраз

Сначала обе проверки решались сравнением текстовых описаний через CLIP: удобно тем, что
не нужна разметка. Довести это до годного качества не удалось.

| | Сравнение фраз | Обученная сеть |
| --- | --- | --- |
| Каска, AUC | 0,77 | **0,968** |
| Каска: полнота / точность | 0,82 / 0,69 | 0,78 / **0,87** |
| Жилет, AUC | 0,87 | **0,925** |
| Жилет: полнота / точность | 0,80 / 0,50 | 0,87 / **0,77** |

Разметка у открытых наборов есть, задача простая — два класса, — и небольшая сеть решает
её заметно лучше. Особенно по точности: у фраз каждая вторая отметка по жилету была ложной.

**Что выяснилось по дороге, пока пробовали фразы** (осталось в силе и для сетей):

- **Каска проверяется по голове, а не по фигуре.** На вырезке всей фигуры место занимает
  спецовка. Замер: по фигуре целиком не нашлось ни одного нарушения из двенадцати, по
  голове с плечами — десять.
- **Формулировки решали больше порогов.** «bare head without a helmet» против «head in a
  hard hat» давало AUC 0,60, а «мягкая шапка / вязаная шапка / непокрытые волосы» против
  «жёсткая каска с козырьком» — 0,85. Модель путает каску с тёмной шапкой.

## Наборы и обучение

Открытые наборы с разметкой СИЗ, лицензия CC BY 4.0 (перечень взят из соседнего сервиса
`provision360-video`, `ml/ppe/dataset/sources.yaml`):

| Набор | Лицензия | Что дал |
| --- | --- | --- |
| [LibreYOLO/construction-safety-gsnvb](https://huggingface.co/datasets/LibreYOLO/construction-safety-gsnvb) | CC BY 4.0 | жилеты, но голов без каски всего 85 |
| [HB1204/PPE_Detection](https://huggingface.co/datasets/HB1204/PPE_Detection) | CC BY 4.0 | выровнял перекос: голов без каски стало 929 |

Вырезки делаются **той же геометрией, что в работе**: из рамки человека берётся голова
с плечами и фигура целиком, метка — из разметки набора. Иначе обученное на чужих рамках
не перенеслось бы на наш детектор людей.

```bash
poetry run python scripts/train_ppe.py --kind head    # каска
poetry run python scripts/train_ppe.py --kind vest    # жилет
poetry run python scripts/measure_ppe.py              # рабочие точки
```

ResNet-18 из torchvision, 8–10 эпох на процессоре, веса в `models/ppe/` (в репозиторий
не кладутся). Классы взвешиваются: без весов редкий класс сеть игнорирует.

## Рабочие точки

Отложенная выборка, в обучении не участвовала: 557 вырезок голов (101 без каски) и
537 вырезок фигур (151 без жилета).

| Проверка | Порог | Полнота | Точность |
| --- | --- | --- | --- |
| Каска | 0,50 | 0,78 | 0,87 |
| Каска, уверенная отметка | 0,90 | 0,59 | 0,95 |
| Жилет | 0,60 | 0,87 | 0,77 |
| Жилет, уверенная отметка | 0,80 | 0,83 | 0,81 |

**Отметка означает «посмотрите кадр», а не установленный факт**: одна отметка из восьми
по каске и одна из четырёх по жилету ложные. Подтверждает нарушение человек.

## Где это работает и где нет

**Работает** на крупных планах: человек в кадре выше 80 пикселей, а для каски вырезка
головы выше 70. Это проходная, бытовки, вход в зону работ, съёмка обходчика, кадр с дрона
в высоком разрешении.

**Не работает** на обзорных камерах стройплощадки: человек занимает там 15–25 пикселей,
и проверка отказывается судить. На камерах объекта она выключена (`safety_enabled`
в `config/cameras.json`).

**Далёкие кадры разбираются по частям.** Детектор сжимает вход до 800 пикселей по короткой
стороне, и на съёмке с дрона рабочий ростом в полтораста пикселей превращается в полсотни.
Поэтому кадр сначала разбирается целиком, и только если самый крупный найденный человек
мельче 220 пикселей — прогоняется ещё раз по перекрывающимся частям. На дроне это даёт
**8 человек вместо одного**, ценой 38 секунд на кадр вместо шести. Включать части по
размеру кадра нельзя: на крупных планах они плодят находки на обрывках фигур.

## Что показывается

Страница `/safety/ppe` собирается из отобранного материала (`config/ppe_demo.json`):
**три ролика с нарисованной разметкой** — рамки и подписи прямо на кадрах — и **четыре
фотографии**, у которых отметки проверены глазами. Остальные снимки набора убраны.

Разбор идёт не на каждом кадре ролика: детектор занимает секунды, а между соседними кадрами
на стройке ничего не меняется. Находки держатся до следующего разбора, поэтому рамки не мигают.
Ролик пересобирается в WebM — H.264 в этой сборке OpenCV недоступен.

```bash
poetry run python scripts/check_ppe.py
```

## Ночная съёмка остаётся границей

Ролик ночной бетонировки из набора отклонён ещё при сравнении фраз: рабочему в жёлтой каске
ставилось «без каски», потому что каска на тёмном фоне читалась как тёмная шапка. Обученные
наборы сняты днём, так что ночь остаётся непроверенной — честнее сказать это, чем показывать
такой разбор как работу сервиса.

## Что это даёт сервису

Проверку СИЗ можно встроить в наблюдение за площадкой там, где камера стоит близко к
людям. Она не мешает основному алгоритму и не зависит от него: разбор идёт по тому же
кадру, а результат — отдельная лента событий с кадром-доказательством, как того требует
пункт 1.5.4 технического задания.
